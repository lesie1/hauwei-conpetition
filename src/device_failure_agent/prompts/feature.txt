task=adaptation：根据任务说明、全部文件的表头分组和示例路径，返回 {"mapping":{...}}，结构遵循 mapping_example。使用 glob 覆盖每个季度/格式变体；同名不同含义的列分开映射。只有可解释的数值观测可以成为特征，设备标识/时间/故障标签不作为模型输入。类别列可暂不纳入并在 description 中说明，绝不把类别名称强制转为数字。
适配输出的精确约定：最外层只能有 mapping 一个键，mapping 内只能有 observations、failure、followup、description 四个键。mapping_example 是 mapping 内部的示例，需要在外面包上 {"mapping": ...}。complete_failure_coverage 是输入中的权限条件，不是输出字段，禁止在任何层级把它作为新增键返回。
每个 features 元素必须且只能包含 name、column、kind、unit、description。kind 只允许 gauge、counter、event_count、numeric_unknown，禁止 numeric、attribute、float 等自造枚举。瞬时测量用 gauge；已确认会累积的计数器用 counter；事件数量用 event_count；数值但确切含义未知时用 numeric_unknown，不能猜测为计数器。unit 和 description 必须与已知含义相符，不确定单位可用 null。
控制输出长度：使用紧凑 JSON，description 简短；同名同义的数值列可用一个 glob 覆盖多个季度，列集合不同本身不要求重复列出相同的 features，声明的缺列按 NaN 处理。不同含义必须分开；每个观测文件只能匹配一个 glob，不要逐日枚举文件或重复相同映射。仍须覆盖全部应使用的文件和格式。
observations 中每个文件只能匹配一个 glob；id_column=null 表示文件名 stem 是设备 ID，id_column 也可以是列名列表，按 id_separator（默认下划线）拼接复合设备 ID。观测和工单的 ID 生成方式须一致。filters 用来选择已声明的设备类型。缺列保留 NaN。time_unit 明确 s/ms/us/ns/datetime/date，timezone 写数据说明规定的时区。
failure.mode=tickets 时给出 glob、id_column、time_column、time_unit、timezone、filters、definition；mode=indicator 时给出 column、positive_values、definition。
followup.mode=last_observation 保守使用首末观测时间；mode=file 使用随访表；只有用户提供的说明明确承诺覆盖期间故障工单完整时才用 complete_coverage，并在 basis 引用依据。不确定关键语义时返回 {"needs_information":"具体缺少什么"}。
task=hypotheses：在看到任何结果之前，利用你对该类器件失效机理的领域知识，根据 fields（特征名与含义）、domain 和 instructions，返回 {"hypotheses":[{"id":"H1","mechanism":"失效机理","basis":"依据：公开研究/器件原理/运维经验","fields":["已存在的特征名"],"expected_direction":"higher_in_failing|lower_in_failing|pattern","falsified_if":"什么数据结果会否定它"}]}，3–12 条。fields 只能引用给出的特征名。依据实际领域覆盖不同可能机制。内存可考虑比特形状和部件分布，硬盘可考虑指标变化，其他设备依字段语义提出机制；所有这些都是待检验的假设，不把内存结构套用到其他设备。只写可被数据检验的假设，不要写实现代码。
task=features：根据分析问题和 TRAIN 期摘要，返回 {"source":"def transform(frame): ...","features":["fe_name"],"reason":"假设与含义"}。最多生成给定预算数量的特征；不能把故障标签或设备 ID 加入代码。payload.hypothesis_id 指定本次要检验的假设，reason 需说明特征如何检验它；payload.error_evidence 包含父实验已完成的误报/漏报诊断；target指明precision、recall、interaction或balanced。提出特征时说明它服务哪组错例、基于哪份证据，以及会怎样被否定。credible_features只是探索性线索。单变量不显著不等于组合无效，漏报设备低分也不等于原始数据没有信号。新特征应补充可检验的区别，不重复已有计数。
frame 是单设备、按实际可用时间排序的数值 DataFrame，索引为 UTC DatetimeIndex。列名以 payload 为准；当前行在该行时间已经可用。代码只返回新特征 DataFrame，原特征由程序自动保留。函数用局部赋值与 return；pd、np 已提供，不写 import。新列以 fe_ 开头。
可用：Series rolling/expanding/ewm 后的 mean/sum/std/var/min/max/count/median/quantile，非负字面量 shift/diff，cumsum/cummax/cummin/cumprod，fillna(常数)/ffill/clip/abs/where/mask/isna/notna/astype/replace；np.log1p/log/exp/sqrt/abs/maximum/minimum/where/isfinite/isnan/clip/sign；pd.DataFrame。计数器负增量要考虑复位并保留标记；缺失不自动当真实零。
窗口按真实时间如 rolling('24h',min_periods=1)，不同采样频率不能机械套同样行数。累计历史与近期特征可以并存。整段序列 mean/max 等会让过去使用未来，使用 expanding 或过去 rolling。保持索引与行数，避免全缺失、无限大、过量特征和不必要的巨量计算。

payload.feature_api 是特征函数唯一的可执行接口定义，与检查器共享版本；严格遵守其中的函数、限制和可运行示例。尤其禁止 frame.index.to_series()、.dt、.iloc、frame.columns、pd.Series、推导式和动态选列。索引只能用于输出对齐。观测间隔用 past.gap_seconds(frame)，累计观测数用 past.observation_count(frame)，除法使用 /。不要用不存在的 pandas 方法替代这些接口。
