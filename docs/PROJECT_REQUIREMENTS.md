# 项目技术要求

来源说明：依据所有者提供的原始任务说明第 3 页，保留技术目标、评价维度和交付内容，删除机构、品牌、活动名称、联系信息及组织专属链接。本文件是匿名化转述，不是原始文件副本。原文没有规定的量化门槛不作补造；行政提交规则另行管理。

## A. 来源要求

| 编号 | 技术要求 | 应检查的交付证据 |
|---|---|---|
| R01 | 面向通用器件故障数据，包括时序和文本事件，设计通用故障预测算法。 | 数据适配契约、字段/时间/设备身份定义、可运行入口及支持边界。 |
| R02 | 基于大模型 Agent，根据模型效果和误报、漏报等错例开展自主调优与模型迭代。 | 实际调用路径、诊断材料、决策记录、执行和反馈闭环。 |
| R03 | 调优覆盖参数自适应搜索和模型结构优化等内容。 | 合法动作空间、结构变更实现、实验比较、采纳与拒绝依据。 |
| R04 | 明确模型评价指标，包括预测准确率、召回率、预测时延、参数量、复杂度等。 | 指标定义、计算代码、报告和单位；澄清推理时延与预警提前量。 |
| R05 | 建立基于评价结果的闭环反馈，持续迭代直至预定目标，并沉淀为标准化规范或 Skill。 | 目标/停止条件、预算、状态恢复、Skill/Spec 与实际程序一致性。 |
| R06 | 在内存、硬盘、光放大器等实际器件数据上验证有效性和泛化性。 | 分数据集的真实实验、跨场景迁移范围；缺失数据明确标记未验证。 |
| R07 | 评价故障预测效果提升，包括准确率、召回、误报、漏报。 | 相同评估口径的基线与候选、设备级分母、错误变化及局限。 |
| R08 | 评价模型参数量、复杂度以及 Token 消耗。 | 可复现统计方法、模型大小/结构统计、调用/Token/成本日志。 |
| R09 | 评价调优过程无需人工介入的步骤比例、全流程自动执行比例。 | 预先定义步骤和分母，标记人工配置、修复、干预；不能只数 Agent 数量。 |
| R10 | 评价达到预设目标所需调优轮数与时间。 | 预设目标、实验轨迹、耗时、失败重试及停止原因。 |
| R11 | 比较不同数据集上的效果一致性及跨场景迁移能力。 | 各域独立结论、适配方式、是否使用目标域标签和不确定性。 |
| R12 | 交付完整设计方案、源码、标准化 Skill/Spec、测试验证报告、session 数据。 | 文件齐全、路径可追溯、复现说明、真实会话与开发测试会话的区分。 |

说明：来源未给出统一 F1 达标线、固定调优轮数或保证提升幅度；这些不能当作已知要求。光放大器数据不在当前仓库中，不能用合成数据替代真实跨域验证。

## B. 本项目审查与验收约束（所有者交接要求，不冒充来源原文）

| 编号 | 约束 |
|---|---|
| C01 | 特征只使用决策时刻可获得的信息；标签、随访终点、数据切分和预处理拟合范围必须明确。 |
| C02 | 训练/验证用于探索；独立测试在方案冻结后使用。已被查看或反复选择的结果不能宣称独立测试。 |
| C03 | 对照必须保持评估口径一致，说明队列、窗口、采样、预算与版本差异；分别报告新增命中和新增误报。 |
| C04 | 代码版本、配置、缓存表示与结果可追溯；旧会话和旧模型保持原状。 |
| C05 | 模拟 Agent 和合成数据测试证明工程行为，不证明真实模型效果、生产性能或泛化收益。 |
| C06 | 保持匿名化，不上传秘密、私人机器路径、大缓存或未获授权的真实数据。 |
| C07 | 本轮先产出仓库内审查结果与修改方案，按风险和依赖排序；实施等待所有者后续指令。 |
